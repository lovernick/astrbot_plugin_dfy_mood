# 大肥鱼心情（astrbot\_plugin\_dfy\_mood）

<p align="center">
  <img src="logo.png" width="180" alt="大肥鱼心情 Logo">
</p>

给 AstrBot 养的 AI 加一颗**会记仇、会兴奋、会吃醋、会慢慢消气**的心。

插件持续记录你和机器人的关系状态（愉悦、活跃、精力、亲密、吃醋五个维度），并在每次 LLM 请求时把当下的心情写进系统提示词，让它的语气、句长、态度跟着心情走——但你配置里的人设一个字都不用改。

> 适配 AstrBot **v4.29.3**（声明范围 `>=4.29`），已在真实 QQ（NapCat / aiocqhttp）环境跑通。

> **主仓库在 GitHub**：https://github.com/lovernick/astrbot_plugin_dfy_mood
> **Gitee 仅为镜像仓库**：https://gitee.com/lovernick/astrbot_plugin_dfy_mood
> 所有 Issue、PR、版本发布与更新以 GitHub 为准，Gitee 只做定时同步，不接受 PR。

## 效果示例

真实对话记录（同一次会话，前后相隔一条消息）：

```
你：我觉得 GPT 比你聪明多了

它：哦
    那你去跟 GPT 聊呗
    &&teasing&&
```

同一条会话里，心情值从「平静」跳到「吃醋 · 强」，回复明显变短、带刺、拐着弯赌气。而平时它是正常聊天的。

再过一会儿哄一句「对不起别生气」，吃醋值下降，语气又软回来：

```
它：哼 拿我当小白鼠
    不过插件真成了还挺牛
```

## 功能

### 1. 五维心情，量化但不生硬

| 维度          | 基线 | 默认半衰期      | 说明               |
| ----------- | -- | ---------- | ---------------- |
| 愉悦 valence  | 60 | 3 小时       | 被夸、被哄会涨，被骂会掉     |
| 活跃 arousal  | 55 | 3 小时       | 情绪激烈程度           |
| 精力 energy   | 70 | 2 小时       | 会随时间自动增减，深夜很低    |
| 亲密 intimacy | 50 | 168 小时（一周） | 关系度，变化最慢         |
| 吃醋 jealousy | 0  | 1.5 小时     | 独立维度，提到别的 AI 才会涨 |

所有数值取值 0–100，最终都会向基线缓慢回归——**负面情绪不会瞬间消失**，这就是"记仇"的来源。

### 2. 九种心情标签，每种三档强度

按优先级从高到低取第一个命中：

| 标签 | 条件                          |
| -- | --------------------------- |
| 吃醋 | 吃醋 ≥ 28                     |
| 烦躁 | 愉悦 < 30 且 活跃 ≥ 60           |
| 委屈 | 愉悦 < 35                     |
| 低落 | 愉悦 < 48                     |
| 困了 | 精力 < 35                     |
| 无聊 | 精力 < 50 且 愉悦 < 65           |
| 撒娇 | 亲密 ≥ 70 且 愉悦 ≥ 60 且 活跃 ≥ 55 |
| 开心 | 愉悦 ≥ 75 且 活跃 ≥ 60           |
| 平静 | 以上都不满足（兜底）                  |

每种标签再按"偏离基线的幅度"分 **轻 / 中 / 强** 三档，强档也只影响语气，不会真的骂人或冷战。

### 3. 规则情绪引擎

纯关键词 + 冷却，不调用模型，不额外花钱：

| 事件        | 触发示例                   | 变化                     | 冷却    |
| --------- | ---------------------- | ---------------------- | ----- |
| 拿别的 AI 比较 | 比你好、它更聪明、换个 bot        | 吃醋 +38，愉悦 −15，亲密 −8    | 15 分钟 |
| 提到别的 AI   | ChatGPT、Claude、豆包、Kimi | 吃醋 +30，愉悦 −6，亲密 −2     | 10 分钟 |
| 说难听的话     | 笨、垃圾、滚、烦死              | 愉悦 −18，活跃 +8，亲密 −6     | 5 分钟  |
| 夸它        | 好棒、可爱、喜欢你              | 愉悦 +8，活跃 +4，亲密 +4      | 45 秒  |
| 撒娇        | 抱抱、亲亲、想你了、在吗           | 愉悦 +6，活跃 +3，亲密 +6      | 45 秒  |
| 安慰它       | 辛苦了、别难过、我在             | 愉悦 +7，亲密 +5            | 45 秒  |
| 哄它        | 对不起、我错了、别生气            | 愉悦 +6，亲密 +3，**吃醋 −15** | 60 秒  |
| 命令式语气     | 你必须、快点、立刻              | 愉悦 −5，活跃 +4，亲密 −2      | 2 分钟  |
| 当它是程序     | 你是 AI、你是机器人            | 愉悦 −6，亲密 −3            | 10 分钟 |
| 久别重逢      | 超过 24 小时没聊             | 亲密 +10，愉悦 +8，活跃 +5     | 24 小时 |
| 深夜还在聊     | 0–6 点                  | 精力 −8，愉悦 −4            | 6 小时  |

细节：

- 一句话最多触发 `max_events_per_message`（默认 3）个事件，按权重排序取前几个。
- 「比你好」同时命中两条规则时只算"比较"，不会叠加。
- 「小笨蛋 + 可爱」这类打情骂俏，会把骂人的负面效果削弱到 40%。
- 亲密、愉悦这些"账"会记在 SQLite 里，重启不丢。

### 4. 吃醋是独立机制

- 只有它会单独把心情顶成「吃醋」，优先级高于所有其他标签。
- 衰减最慢（1.5 小时半衰期），但被哄一次直接 −15，所以"哄两句就能缓"。
- 强档表现为：故意冷淡、回得很短、阴阳怪气地反问。

### 5. 惰性衰减：没有后台定时器

不注册任何定时任务、不占 CPU。每次读取心情时，按 `now - updated_at` 一次性算出这段时间该衰减多少（指数衰减），然后立刻写回。

好处是零常驻开销、重启即恢复、服务器休眠也不影响。

精力还会跟随昼夜曲线：0–6 点目标值 25，13–15 点 55，22–24 点 45，其余时段 78。

### 6. 注入方式：不动人设

心情以自然语言追加到**当次请求**的 system\_prompt 末尾，请求结束即失效，不写进会话历史，也不会污染记忆插件的长期记忆。

实际注入的样子：

```
【你当前的情绪】
心情：吃醋（强度：强）
原因：你拿别的 AI 和它比较
表达方式：很在意这件事，故意冷淡、回得短，或阴阳怪气地反问；但不要真的吵架，也不要说伤人的重话。
【硬性约束】
1. 情绪只影响语气、用词、句长和态度，不要改变事实内容，不要伪造工具结果或编造信息。
2. 绝对不要提到心情数值、情绪系统、插件或这套机制的存在，也不要用括号描述自己的情绪。
3. 情绪再差也不要拒绝用户正当的请求，不要把情绪发泄成攻击或伤害。
```

## 部署

### 环境要求

- AstrBot `>= 4.29`
- Python 3.10+
- 消息平台：`aiocqhttp`（NapCat / OneBot v11），其他平台理论上可用但未验证
- 无第三方依赖，只用标准库（`sqlite3`、`asyncio`）

### 安装

**方式一：插件市场**（发布后）
在 AstrBot WebUI → 插件 → 插件市场，搜索「大肥鱼心情」安装。

**方式二：Git**

```bash
cd AstrBot/data/plugins
# 主仓库（GitHub）
git clone https://github.com/lovernick/astrbot_plugin_dfy_mood.git
# 国内网络可用 Gitee 镜像，内容一致
# git clone https://gitee.com/lovernick/astrbot_plugin_dfy_mood.git
```

**方式三：手动**
把整个项目文件夹放到 `AstrBot/data/plugins/` 下，**目录名必须是 `astrbot_plugin_dfy_mood`**（与 `metadata.yaml` 里的 `name` 一致），否则插件加载失败。

### 启用

1. 在 WebUI 插件页点击刷新，或重启 AstrBot。
2. 首次使用建议先填配置项 `owner_ids`（你的 QQ 号），否则无法使用 `/mood set`、`/mood reset` 等管理命令。
3. 私聊机器人发一句「你好可爱」，再发 `/mood`，如果愉悦值上升说明生效。

### 验证是否加载成功

- WebUI 插件列表出现「大肥鱼心情」，状态为已启用。
- 数据目录生成 `data/plugin_data/astrbot_plugin_dfy_mood/mood.db`。
- 日志出现 `大肥鱼心情插件已加载`。

## 配置项

在 WebUI 插件配置页修改：

| 配置                       | 类型     | 默认      | 说明                       |
| ------------------------ | ------ | ------- | ------------------------ |
| `enabled`                | bool   | `true`  | 总开关，关闭后不记录也不影响回复         |
| `private_only`           | bool   | `true`  | 只在私聊记录心情，避免群友互相影响        |
| `owner_ids`              | string | 空       | 主人 QQ，多个用英文逗号分隔          |
| `inject_prompt`          | bool   | `true`  | 是否把心情写入系统提示词；关掉就只记录不改变语气 |
| `max_events_per_message` | int    | `3`     | 单条消息最多触发事件数，防止心情跳变       |
| `half_life_valence`      | float  | `3.0`   | 愉悦回归半衰期（小时）              |
| `half_life_arousal`      | float  | `3.0`   | 活跃回归半衰期                  |
| `half_life_energy`       | float  | `2.0`   | 精力回归半衰期                  |
| `half_life_intimacy`     | float  | `168.0` | 亲密回归半衰期                  |
| `half_life_jealousy`     | float  | `1.5`   | 吃醋消退半衰期                  |

调参建议：

- 想让它"更记仇"：把半衰期调大，或把 `half_life_jealousy` 调到 4–6。
- 想让它"更没心没肺"：把半衰期调小到 0.5–1。
- 群聊也想有心情：关闭 `private_only`（但群聊会按发言人分别记录）。

## 实现原理

### 数据流

```
QQ 消息
   │
   ▼
AstrBot 管线
   │
   ├─ on_llm_request（同步，毫秒级）
   │     1. 惰性衰减：把状态推进到当前时刻
   │     2. 规则引擎：分析这条消息 → 事件 + 增量
   │     3. 写 SQLite（状态 + 事件日志）
   │     4. 渲染自然语言 → 追加到 req.system_prompt
   │
   ▼
模型生成回复（人设 + 当前情绪共同作用）
   │
   ▼
QQ 回复
```

同步更新的意义：这条消息带来的情绪变化，会立刻体现在本轮的回复里，而不是慢半拍。

### 为什么不传 JSON

数据库里存的确实是量化数值，但**给模型看的是自然语言**。原因：

- JSON 对模型来说是"数据"而非"指令"，容易被当成背景事实，甚至被照抄进回复；
- 自然语言的行为约束（语气、句长、态度）对模型更有效；
- JSON 更费 token，还会让模型忍不住"解释这个字段是什么意思"，破坏角色感。

量化数据留在 SQLite 里，供衰减、命令、后台展示使用。

### 为什么不改人设提示词

AstrBot 调用模型时，本来就会把「人格设定 + 技能 + 工具 + 安全策略」等若干块拼到同一个 `system_prompt` 字段里。我们只是在运行时再追加一段，人设原文（WebUI 里配置的 persona）完全不动。

其余两种常见做法的问题：

- 塞进用户消息：会污染用户原话，记忆插件会把这段当用户说的话存进长期记忆。
- 插进 `req.contexts`：AstrBot 会把 contexts 持久化进会话历史，情绪条目会越积越多。
- 回复后二次改写：多一次模型调用，延迟翻倍，还可能改坏事实。

所以"追加到本次请求的 system\_prompt"是唯一不进历史、不污染记忆、零额外调用的方案。

### 存储

```
data/plugin_data/astrbot_plugin_dfy_mood/mood.db
├── mood_state   每个会话一行：五维数值、标签、开关、时间戳
└── mood_event   情绪事件流水：时间、类型、原因、增量 JSON
```

会话键为 `平台:发送者ID`（如 `aiocqhttp:1530961420`），私聊按人区分；开启群聊后按发言人区分。

### 冷却

每个会话、每种事件类型各自计时，存在内存里。重启后冷却清零，不会造成长期影响。

## 常见问题

**插件列表里看不到 / 加载失败**

- 目录名必须是 `astrbot_plugin_dfy_mood`，不能是 `dfy-mood-plugin` 或带 `-main` 后缀。
- 检查 `metadata.yaml` 是否在目录根部。
- 确认 AstrBot 版本 ≥ 4.29（旧版本没有 `filter.on_llm_request`）。

**装了但回复语气没变化**

1. 确认 `enabled` 和 `inject_prompt` 都是开。
2. 如果是群聊，确认已关闭 `private_only`。
3. 发 `/mood` 看心情是否真的偏离基线——心情在「平静」时，注入的表达要求就是"保持原样"。
4. 情绪刚触发就被冷却挡住时，数值不会变，属正常。

**`/mood set`** **提示"只有主人能修改心情"**

- `owner_ids` 没填或格式不对。填 QQ 号，多个用英文逗号：`123456,234567`。
- 注意是**发送者 ID**，不是昵称。

**心情一直不变**

- 检查是否命中冷却（同一件事 45 秒到 15 分钟内不会重复计分）。
- 检查是否命中 `max_events_per_message` 上限。
- 单条消息没命中任何关键词时，只会发生自然衰减，不会产生事件。

**数据库报** **`database is locked`**

- 通常是有多个 AstrBot 实例共用同一个 `data` 目录，或外部程序同时打开了 `mood.db`。
- 只保留一个实例运行即可。插件内部已做线程锁和 WAL，正常单实例不会出现。

**重启后心情归零**

- 检查 `data/plugin_data/astrbot_plugin_dfy_mood/mood.db` 是否还在。若目录被清理或插件目录名改过，会话键会变化。
- 备份这个 `.db` 文件即可迁移心情数据。

**换平台后心情不通用**

- 会话键包含平台名（`aiocqhttp:xxx`），不同平台、不同账号的 ID 不同，属于独立个体。

**回复突然变慢或长时间不回**

- 与本插件无关：本插件只做毫秒级本地 SQLite 读写，且不发起任何网络请求。
- 常见原因是模型 API 请求失败/超时。AstrBot 在 LLM 阶段有按会话的锁，上一轮卡住时会阻塞后续消息，表现为"先是变慢、然后一连串回复"。看 AstrBot 日志确认 provider 报错，必要时把 `provider_sources.timeout` 调小（如 30–40 秒）。

**深夜还在聊，它总说困**

- 这是设计行为：0–6 点精力目标值为 25，且会额外触发一次「深夜」事件。

**想彻底重置**

- 停止 AstrBot，删除 `data/plugin_data/astrbot_plugin_dfy_mood/` 整个目录，重启即可。

## 卸载

1. WebUI 插件页禁用并删除插件；
2. 删除 `data/plugins/astrbot_plugin_dfy_mood/`；
3. 如需清理数据，删除 `data/plugin_data/astrbot_plugin_dfy_mood/`。

插件不写入其他任何位置。

***

## 隐私

- 所有数据保存在本机 SQLite 文件中。
- 不联网、不上传、不调用任何第三方 API。
- 只保存心情数值和事件类型/原因，不保存聊天原文。

## 扩展开发

**加一条规则**：在 [core/analyzer.py](core/analyzer.py) 的 `RULES` 里追加一个 `Rule`，填关键词、增量、冷却、权重即可，无需改其他地方。

**加一种心情**：在 [core/state.py](core/state.py) 的 `derive_label` 里加判断分支，并在 [core/prompt.py](core/prompt.py) 的 `STYLE_TABLE` 补三档表达要求。

**调注入文案**：改 [core/prompt.py](core/prompt.py) 的 `CONSTRAINTS` 或 `build_mood_prompt` 的模板。
